# External GitHub Components — Reuse Strategy

## Career-Ops

Treat as a primary reference/reuse candidate for:
- job discovery;
- evaluation;
- application tracking;
- data contracts;
- Claude Code skills;
- existing provider architecture.

Inspect before rewriting.

## Awesome Remote Job

Use as a source catalogue/discovery reference.

It is not proof that a job is active or eligible.

## Jobicy

Evaluate as a structured remote-job source/API and reuse existing Career-Ops integration if available and appropriate.

## JobsCollider

Evaluate as an additional remote-job feed where terms/licensing permit.

Preserve source attribution and do not redistribute data contrary to its terms.

## JobSpy / JobTrail

Study for multi-source discovery and normalisation patterns. Do not blindly copy scraping logic.

## JobSync / MCP-enabled trackers

Study MCP/API patterns and application tracking ideas.

## General rule

For every external GitHub component:
1. inspect licence;
2. inspect terms;
3. inspect maintenance/activity;
4. inspect security;
5. inspect code quality;
6. decide reuse vs adapter vs inspiration;
7. document decision in ADR when material.
