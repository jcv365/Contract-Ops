# Business Requirements

## User

Primary user is a senior Principal Hybrid Cloud Architect and consultant seeking international remote contract work.

The approved profile and evidence must come from the user's actual profile repository/data. Do not hard-code unverified biography into code.

## Contract preferences

The HUNT rules must be configurable, but Phase 1 should support:
- worldwide search;
- remote-first/fully remote priority;
- contract/freelance/SOW/project engagements;
- senior/principal/architect-level work;
- Azure, hybrid cloud, enterprise platform, infrastructure, networking, FinOps, AI/platform architecture and adjacent architecture roles;
- rejection/exclusion of permanent roles unless explicitly enabled;
- rejection/exclusion of onsite/hybrid roles unless explicitly enabled;
- rejection of mandatory security clearance unless explicitly marked as an exception;
- rejection of mandatory incompatible work authorisation;
- language requirements as a scored/validated eligibility factor.

## Worldwide

Worldwide means the configured country/region matrix, not a marketing label.

The system must show:
- countries searched;
- regions searched;
- sources searched;
- search patterns used;
- failed/unavailable sources;
- last search time;
- coverage percentage.

## Recruiter outreach

The system should find recruiters even when they have no currently suitable advert.

A recruiter target is email-ready only when there is a verified usable email.

## Professional company outreach

The system should find companies that may:
- use contractors;
- deliver cloud transformation;
- subcontract specialist architecture;
- operate cloud/infrastructure practices;
- run enterprise transformation programmes.

The system should identify likely contacts and their role, but must not invent an email.

## Evidence

All claims must map to approved evidence records.
